# Papers 01–02 integration review

**Mode:** structural read plus bounded close read

**Scope:** `papers/01-design-map/main.tex`, `papers/02-formal-dynamics/main.tex`, their outlines, model, claim ledgers, logical-claims audits, and the shared TDRG draft
**Boundary:** manuscript integration only; no theorem, simulation, citation-identity, compilation, or publication review was performed

## Bottom line

The papers share a coherent design direction, but they do not yet share a canonical semantic contract. Before either draft grows, fix four program-level interfaces: (1) MCRP core versus optional TDRG governance, (2) the exact scope and time signature of a reliance view, (3) one resource vector and an explicit assessment-mode crosswalk, and (4) the contribution/dependency boundary between synthesis (Paper 01) and formal evaluation (Paper 02). The existing claim ledgers appropriately block the central performance, anonymity, bridge, and fork claims; several manuscript sentences nevertheless read more strongly than those ledgers permit.

Severity meanings: **High** blocks coherent cross-paper development or could create a materially false claim; **Medium** should be repaired before external close review; **Low** is editorial consistency.

## Canonical cross-paper contract to adopt

| Concept | Paper 01 role | Paper 02 role | Required shared meaning |
|---|---|---|---|
| MCRP scientific record | Define/map requirements and epistemic distinctions | Treat the versioned claim/evidence release as an exogenous review-request input | Governance never rewrites claims, evidence, executions, or scientific dispositions |
| TDRG | Identify as optional governance profile and map its interface | Formalize and compare candidate evaluator/policy behavior | Outside MCRP core until privacy, interoperability, replay, and empirical promotion gates pass |
| Reliance view | Conceptual interface | Formal query and output | Root/domain/topic/capability/role/case/policy/event-cut/evaluation-time relative; never a verdict or intrinsic actor property |
| Resource profile | Canonical multiaxis declaration plus R0 | Feasibility constraints and costs under the same schema (or declared projection) | Resource level is orthogonal to epistemic achievement; human and agent capacities are not fungible by default |
| Bridge | Importer-approved scoped reliance interface | Formal object and influence experiment | Imports eligibility/evidence semantics under explicit bounds; does not launder claim truth or sanctions |
| Fork | Governance/policy exit over common record | Deterministic dependency-separation and adversarial experiment | Preserves common public record; private state does not copy by default; no claim of truth or real-world capture containment |
| Fresh persona | Conditional privacy requirement | Observer-relative observability/security model | One persona per review case; unlinkability is conditional and accountability introduces explicit trusted services/coalitions |

## Recommended repair order

1. Freeze the glossary, MCRP/TDRG boundary, canonical view signature, resource vector, and mode crosswalk in a shared program note.
2. Revise both introductions/contribution lists to enforce the Paper-01/Paper-02/Paper-03 division of labor.
3. Align bridges, forks, time semantics, R0 terminology, and anonymity language to that contract.
4. Narrow the result-like sentences to match the current blocked claim ledgers.
5. Complete the two bounded primary-source gap audits before adding further narrative or formal claims.

No contradiction was found in the papers’ core safety posture: both reject a global actor score as scientific truth, keep event types separate, require importer-authorized bridges, preserve forked access to a common public record, treat downselects as weaker than full execution, and explicitly reserve scientific validity for human/domain judgment. The integration problem is precision and division of labor, not a divergent underlying design.
