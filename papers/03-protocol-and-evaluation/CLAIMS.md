## Evidence promotion rules

1. Change an `I` row to supported only when the exact code release, environment, fixture set, command, and report digest are cited.
2. Convert an `H` row to an `E` row only after the confirmatory design is frozen, the run is complete, uncertainty and subgroup harms are reported, and the result survives its stated failure condition.
3. Split partial or heterogeneous findings into separate claims; never mark a composite row supported because one component passed.
4. Record null, adverse, and stopped results in the ledger and manuscript.
5. A later failed freshness rerun creates a visible supersession/adverse-status entry; it does not silently erase the original run.
